### 1. FRadio — `isChecked` 判断有误 ✅ **属实**

**文件**: `packages/fit-ui/src/FRadio/index.vue:118`

**当前代码**：
```ts
const isChecked = computed(() => {
  if (isGroup.value && radioGroup) {
    return radioGroup.modelValue.value === props.value
  }
  return props.modelValue === props.value || props.modelValue === true
})
```

**问题分析**：
- 当独立使用 FRadio 且 `modelValue=true` 时，无论 `value` 是什么，`isChecked` 都返回 `true`
- 这会导致多个独立 radio 同时显示为选中状态

**示例场景**：
```vue
<FRadio v-model="checked1" :value="1" label="选项 1" />
<FRadio v-model="checked2" :value="2" label="选项 2" />

<!-- 如果 checked1=true, checked2=false，两个 radio 都会高亮 -->
```

**建议修复**：
```ts
// 方案 1：去掉 `|| props.modelValue === true` 分支
return props.modelValue === props.value

// 方案 2：独立使用时专门处理布尔值
if (isGroup.value && radioGroup) {
  return radioGroup.modelValue.value === props.value
}
// 独立使用时，如果是布尔值则直接比较
if (typeof props.modelValue === 'boolean') {
  return props.modelValue && props.value === true
}
return props.modelValue === props.value
```

**严重程度**：🔴 **高** - 功能逻辑错误

### 2. FPagination — 切换 `pageSize` 后当前页未校正 ✅ **属实**

**文件**: `packages/fit-ui/src/FPagination/index.vue:201-203`

**当前代码**：
```ts
function handleSizeChange() {
  emit('update:pageSize', innerPageSize.value)
  emit('size-change', props.currentPage, innerPageSize.value)
  // ❌ 缺少：若 currentPage > newPageCount，需重置到最后一页
}
```

**问题分析**：
- 假设总记录数 100 条，当前在第 10 页（每页 10 条）
- 用户将 pageSize 改为 50 条/页，总页数变为 2 页
- 但 `currentPage` 仍为 10，超出有效范围

**影响**：
- 父组件若不手动处理，会显示空数据（因为第 10 页不存在）
- 用户体验差

**建议修复**：
```ts
function handleSizeChange() {
  const newPageSize = innerPageSize.value
  const newPageCount = Math.ceil(props.total / newPageSize)
  
  // 如果当前页超出范围，重置到最后一页
  if (props.currentPage > newPageCount && newPageCount > 0) {
    emit('update:currentPage', newPageCount)
  }
  
  emit('update:pageSize', newPageSize)
  emit('size-change', props.currentPage, newPageSize)
}
```

**严重程度**：🟡 **中** - 边界情况处理缺失

### 3. FTabs — 键盘导航不跳过禁用 tab ✅ **属实**

**文件**: `packages/fit-ui/src/FTabs/index.vue:261-268`

**当前代码**：
```ts
const handleKeyDown = (currentIndex: number, direction: 'left' | 'right') => {
  const nextIndex = direction === 'left' 
    ? (currentIndex - 1 + tabList.value.length) % tabList.value.length
    : (currentIndex + 1) % tabList.value.length
  
  const nextTab = tabList.value[nextIndex]
  const nextKey = nextTab.key ?? nextTab.name ?? nextIndex
  handleTabClick(nextTab, nextIndex)  // ❌ 直接调用，没有检查 disabled
}
```

**问题分析**：
- 按方向键会聚焦到 disabled tab 上
- `handleTabClick` 内部有 `if (tab.disabled) return`，所以不会真正切换
- 但用户感觉按方向键"没反应"，体验不好

**建议修复**：
```ts
const handleKeyDown = (currentIndex: number, direction: 'left' | 'right') => {
  let nextIndex = currentIndex
  const step = direction === 'left' ? -1 : 1
  
  // 循环查找下一个可用的 tab
  for (let i = 0; i < tabList.value.length; i++) {
    nextIndex = (nextIndex + step + tabList.value.length) % tabList.value.length
    const nextTab = tabList.value[nextIndex]
    
    // 跳过禁用的 tab
    if (!nextTab.disabled) {
      const nextKey = nextTab.key ?? nextTab.name ?? nextIndex
      handleTabClick(nextTab, nextIndex)
      return
    }
  }
}
```

**严重程度**：🟢 **低** - 用户体验问题

### 4. FSelect — 远程搜索无防抖 ✅ **属实**

**文件**: `packages/fit-ui/src/FSelect/index.vue:401-405`

**当前代码**：
```ts
function handleInput() {
  if (props.remote && props.remoteMethod) {
    props.remoteMethod(query.value)  // ❌ 每个按键都触发
  }
}
```

**问题分析**：
- 用户快速输入"中华人民共和国"会触发 7 次远程搜索
- 对服务器造成不必要压力
- 可能导致旧请求覆盖新请求的结果

**建议修复**：
```ts
import { ref } from 'vue'

const searchTimer = ref<any>(null)

function handleInput() {
  if (props.remote && props.remoteMethod) {
    // 清除之前的定时器
    if (searchTimer.value) {
      clearTimeout(searchTimer.value)
    }
    
    // 300ms 防抖
    searchTimer.value = setTimeout(() => {
      props.remoteMethod(query.value)
    }, 300)
  }
}

// 组件卸载时清理
onUnmounted(() => {
  if (searchTimer.value) {
    clearTimeout(searchTimer.value)
  }
})
```

**严重程度**：🟡 **中** - 性能优化问题

### 6. FModal — 焦点恢复被调用两次 ⚠️ **部分属实**

**文件**: `packages/fit-ui/src/FModal/index.vue:439, 462`

**当前代码**：
```ts
// watch 里（modelValue 变 false 时）
unlockBodyScroll()
restorePreviousFocus()  // 第一次

// onUnmounted 里
unlockBodyScroll()
restorePreviousFocus()  // 第二次（如果是在打开状态下销毁组件）
```

**分析**：
- 正常关闭流程：watch 触发 → onUnmounted 触发（组件销毁）
- 确实会调用两次，但 `restorePreviousFocus()` 调用两次无害（焦点已在正确位置）
- `unlockBodyScroll()` 调用两次也 harmless（重复设置 overflow 为原值）

**建议优化**（非必须）：
```ts
let isCleanedUp = false

const cleanup = () => {
  if (isCleanedUp) return
  isCleanedUp = true
  unlockBodyScroll()
  restorePreviousFocus()
}

watch(() => props.modelValue, async (newValue) => {
  if (newValue) {
    savePreviousFocus()
    lockBodyScroll()
    // ...
  } else {
    cleanup()  // 统一清理
  }
})

onUnmounted(() => {
  cleanup()
})
```

**严重程度**：🟢 **低** - 代码优化建议

### 7. FSelect — `getOptionsFromSlots()` 每次渲染都遍历 VNode ⚠️ **部分属实**

**文件**: `packages/fit-ui/src/FSelect/index.vue:249-280`

**当前代码**：
```ts
const selectedOptions = computed(() => {
  const modelValue = props.modelValue
  if (props.multiple && Array.isArray(modelValue)) {
    return getAllOptions().filter(opt => modelValue.includes(opt.value))
  }
  // ...
})

function getAllOptions(): SelectOption[] {
  // ...
  const slotOptions = getOptionsFromSlots()  // ❌ 每次都遍历
  // ...
}

function getOptionsFromSlots(): SelectOption[] {
  const result: SelectOption[] = []
  const defaultSlot = slots.default?.()  // ❌ 每次都获取
  // 遍历 VNode 树...
}
```

**分析**：
- `selectedOptions` 是 computed，依赖 `getAllOptions()`
- `getAllOptions()` 每次都调用 `getOptionsFromSlots()` 遍历 slot VNode
- 当 options 较多或更新频繁时确实有性能隐患

**但实际情况**：
- computed 有缓存机制，只有依赖变化时才重新计算
- 只有当 `props.modelValue` 变化或 `props.options` 变化时才会重新计算
- 不是"每次渲染"都遍历，而是"每次依赖变化"才遍历

**建议优化**（如果需要）：
```ts
// 将 slot options 缓存为独立的 computed
const slotOptions = computed(() => {
  return getOptionsFromSlots()
})

function getAllOptions(): SelectOption[] {
  // 优先使用插槽选项
  const slotOpts = slotOptions.value
  if (slotOpts.length > 0) {
    return slotOpts
  }
  // 否则使用 props.options
  // ...
}
```

**严重程度**：🟢 **低** - 性能优化建议
